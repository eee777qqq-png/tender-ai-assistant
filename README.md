# tender-ai-assistant

Автоматизация подготовки к участию в госзакупках для СМСП (см.
[CLAUDE.md](CLAUDE.md) — полный контекст продукта и протокол контроля
качества). Пока реализовано два агента конвейера:

- **Агент 1 (Монитор ЕИС)** — клиент сервиса отдачи информации ЕИС
  (`zakupki.gov.ru`) по подтверждённому официальной инструкцией протоколу
  (см. [docs/eis-integration-instruction-2025.pdf](docs/eis-integration-instruction-2025.pdf)):
  забирает документы по региону заказчика за конкретную дату и сам
  отфильтровывает те, что относятся к разделу «Строительство».
- **Агент 11 (Онбординг клиента)** — модель профиля клиента (4 блока полей
  + статусная модель) и проверка на полноту/достоверность перед тем, как
  профилем воспользуется Агент 6.
- **Метрика готовности к выборочному аудиту** (общая инфраструктура для
  агентов 3, 4, 6) — трекер, который решает, можно ли перевести агента с
  полной проверки эксперта на выборочный аудит, по правилам протокола
  контроля качества.
- **Лог расхождений** (часть ТЗ Агента 4) — структурированная запись, что
  именно эксперт поправил в выдаче агента, плюс статистика по самым частым
  расхождениям.
- **Агент 2 (Классификатор)** — справочник ОКПД2 по разделу «Строительство»
  (коды 41/42/43, 548 записей из официального классификатора) и проверка,
  относится ли код закупки к строительству. По решению владельца — весь
  раздел «Строительство» в скоупе, без сужения под нишу капремонта.

## Доступ к ЕИС: что реально нужно (проверено по официальной инструкции)

Хорошая новость: отдельного соглашения с Федеральным казначейством
**не требуется**. Доступ оформляется самостоятельной регистрацией через
ЕСИА (Госуслуги) в личном кабинете ЕИС:

1. Зайти на [zakupki.gov.ru](https://zakupki.gov.ru/epz/main/public/home.html)
   → «Все разделы» → «Дополнительная информация» → «Открытые данные» →
   «Получение открытых данных».
2. Авторизоваться подтверждённой учётной записью руководителя организации
   в ЕСИА (для юрлица) или физлица (для ИП).
3. Зарегистрировать нового потребителя машиночитаемых данных, указать цель
   получения данных.
4. Для юрлица — загрузить сертификат руководителя/организации (им же
   потом устанавливается mTLS-соединение с сервисом, отдельный сертификат
   для транспорта не нужен). Для физлица/ИП — получить токен.

Подробности и скриншоты — в
[docs/eis-integration-instruction-2025.pdf](docs/eis-integration-instruction-2025.pdf)
(официальная «Инструкция по использованию сервисов отдачи информации ЕИС»,
2025 год, разделы 3–6).

**Что сервис умеет и чего не умеет:**
- Отбор документов только по региону заказчика + подсистеме + типу
  документа + **одной конкретной дате** за запрос (`exactDate`) — диапазон
  дат не поддерживается, для мониторинга нужно опрашивать сервис за каждый
  день.
- **Фильтра по ОКПД2 на стороне ЕИС нет.** Именно поэтому в проекте есть
  Агент 2 (`classifier.ConstructionClassifier`) — документы скачиваются
  целиком по региону, а на «стройку» отфильтровываются уже у нас.
- Открытый вопрос: точный `subsystemType`/`documentType44` для реестра
  *извещений* (закупки, которые ещё можно выиграть), а не уже заключённых
  контрактов — он приведён в «Альбоме ТФФ ЕИС» (раздел 2.9.19), который не
  входит в общедоступную инструкцию. Сейчас в конфиге стоят значения из
  примера в инструкции (`RGK`/`contract` — реестр контрактов), их нужно
  заменить на код реестра извещений, когда он будет уточнён.
- Если сертификат юрлица на ГОСТ-криптографии (частый случай), `requests`
  не сможет установить с ним TLS-соединение напрямую — используйте
  локальный туннель `stunnel-msspi` + КриптоПро CSP, точная инструкция по
  настройке для Windows Server и Linux — в Приложениях 3–4 того же PDF
  (сервис слушает `int44.zakupki.gov.ru:443`, а клиент стучится в
  `http://localhost:8080`, куда туннель прозрачно домаршрутизирует TLS).

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/macOS
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env`:

   ```bash
   copy .env.example .env
   ```

2. Заполните в `.env` (полный справочник полей — в самом `.env.example`):
   - `EIS_CONSUMER_TYPE` — `legal_entity` или `individual_person`.
   - Для `legal_entity`: `EIS_CLIENT_CERT` / `EIS_CLIENT_KEY` (положите файлы
     в `certs/`, эта папка уже в `.gitignore`). Для `individual_person`:
     `EIS_INDIVIDUAL_PERSON_TOKEN`.
   - `EIS_ORG_REGION` — код региона (`77` = Москва).
   - `EIS_SUBSYSTEM_TYPE` / `EIS_DOCUMENT_TYPE44` — см. предупреждение выше
     про реестр контрактов vs реестр извещений.

## Запуск

```bash
python src/fetch_purchases.py --date 2026-09-15
python src/fetch_purchases.py --date 2026-09-15 --out docs.csv
```

Дата обязательна к смыслу (по умолчанию — вчера), потому что сервис не
поддерживает диапазон дат — только один `exactDate` за запрос.

При ошибке конфигурации или недоступности сервиса скрипт печатает понятную
причину (нет сертификата, сетевая ошибка, SOAP fault) и завершается с
кодом 1.

## Профиль клиента (Агент 11)

```python
from onboarding import ClientProfile, LegalInfo, validate_profile

profile = ClientProfile(client_id="client-1", legal=LegalInfo(inn="7701234567", ...))
issues = validate_profile(profile)  # заполняет profile.status

if profile.is_ready_for_agent_6():
    ...  # можно передавать профиль дальше по конвейеру
else:
    for issue in issues:
        print(issue.block, issue.field, issue.message)
```

`validate_profile()` проверяет заполненность всех 4 блоков (юр.данные,
допуски/опыт, мощности, финансовая готовность) и базовую достоверность
форматов (ИНН, ОГРН, email, телефон), выставляя `profile.status` в
`DRAFT` / `REJECTED` / `VERIFIED`. Согласно протоколу контроля качества,
Агент 6 обязан проверять `profile.is_ready_for_agent_6()` перед
использованием данных клиента.

## Метрика готовности к выборочному аудиту (агенты 3, 4, 6)

```python
from quality_control import AuditReadinessRegistry

registry = AuditReadinessRegistry()
tracker = registry.get("agent_4_smetchik")

# после каждой проверки эксперта над выдачей агента:
tracker.record_check(needed_correction=False)  # или True, если эксперт правил

if tracker.requires_human_review():
    ...  # выдача обязательно идёт на проверку эксперта
else:
    ...  # агент в режиме выборочного аудита
```

Правила зашиты в `AuditReadinessTracker` по протоколу контроля качества:
скользящее окно последних 50 проверок, переход на выборочный аудит при
≥90% без существенной корректировки и 0 критических ошибок в окне; любая
критическая ошибка после перехода — немедленный откат на полную проверку
эксперта с историей в `tracker.rollback_history`.

### Лог расхождений (Агент 4)

```python
from quality_control import DiscrepancyLog

log = DiscrepancyLog()
log.log(
    agent_name="agent_4_smetchik",
    check_id="smeta-2026-001",
    field_name="unit_price",
    agent_value="1200",
    expert_value="1350",
    critical=False,
    note="расценка ГЭСН взята для другого региона",
)

log.most_common_fields("agent_4_smetchik")  # где агент чаще всего ошибается
log.critical_count("agent_4_smetchik")
```

## Классификатор ОКПД2 «Строительство» (Агент 2)

```python
from classifier import ConstructionClassifier

classifier = ConstructionClassifier()
classifier.is_construction_code("41.20.10.110")  # True
match = classifier.classify("43.99.90.280")
print(match.name)  # человекочитаемое название по справочнику

classifier.search("реставрации")  # все коды, где в названии есть это слово
```

Справочник (`data/okpd2_construction.csv`) — это весь официальный раздел
ОКПД2 «Строительство» (коды 41, 42, 43, все уровни, 548 записей). По
решению владельца продукта в скоуп идёт вся стройка целиком, без сужения
под нишу пилота (капремонт).
