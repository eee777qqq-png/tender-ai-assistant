# tender-ai-assistant

Прототип клиента к SOAP-сервису ЕИС (Единая информационная система в сфере
закупок, `zakupki.gov.ru`) для выгрузки реестра закупок по кодам ОКПД2 из
раздела «Строительство» для региона Москва.

## Важно: это не готовый к бою скрипт, а каркас

Настоящий SOAP-сервис ЕИС — закрытый B2G-интерфейс. Чтобы он реально
заработал, вам нужно, до всякого кода:

1. **Заключить соглашение об информационном взаимодействии** с Федеральным
   казначейством / оператором ЕИС. Без него доступа к WSDL нет вообще.
2. **Получить сертификат** для двусторонней аутентификации (mTLS) —
   обычно выпускается на ГОСТ-криптографии через аккредитованный УЦ.
3. **Получить точный WSDL и регламент** (описание операций, структуры
   запроса/ответа, коды регионов и справочники) — это выдаётся вместе с
   доступом и различается между тестовым контуром (`int44.zakupki.gov.ru`)
   и промышленным.

Код в этом репозитории — это структура клиента (конфиг, mTLS-транспорт,
маппинг ответа в Python-объекты, CLI), куда вы подставляете реальные
значения `EIS_WSDL_URL`, `EIS_OPERATION_NAME` и структуру полей запроса из
своего регламента. Названия SOAP-операции и полей фильтра в
[`src/eis_client/client.py`](src/eis_client/client.py) — правдоподобные
заглушки, а не проверенный боевой контракт; их нужно свести к тому, что
реально придёт в вашем WSDL.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/macOS
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env`:

   ```bash
   copy .env.example .env
   ```

2. Заполните в `.env`:
   - `EIS_WSDL_URL` — адрес WSDL, который вам выдал оператор ЕИС.
   - `EIS_OPERATION_NAME` — название SOAP-операции выгрузки закупок из WSDL.
   - `EIS_CLIENT_CERT` / `EIS_CLIENT_KEY` — пути к клиентскому сертификату
     и приватному ключу для mTLS (положите файлы в `certs/`, эта папка
     уже в `.gitignore`, чтобы не закоммитить секреты).
   - `EIS_REGION_CODE` — код региона (`77` = Москва).
   - `EIS_OKPD2_CODES` — коды ОКПД2 через запятую (по умолчанию `41,42,43`
     — разделы «Строительство зданий», «Инженерные сооружения», «Работы
     строительные специализированные»; сузьте список под свою задачу).

## Запуск

```bash
python src/fetch_purchases.py
python src/fetch_purchases.py --okpd2 41.20,42.11 --region 77 --limit 20
python src/fetch_purchases.py --out purchases.csv
```

При ошибке конфигурации или недоступности сервиса скрипт печатает понятную
причину (нет сертификата, не найдена операция в WSDL, сетевая ошибка,
SOAP fault) и завершается с кодом 1.

Если не уверены, как называется нужная операция в вашем WSDL, вызовите
`EISClient.list_operations()` — метод перечислит все операции, доступные в
загруженной схеме.

## ГОСТ и КриптоПро

Если сертификат ЕИС выпущен на ГОСТ-алгоритмах (частый случай для
российских B2G-сервисов), стандартный `ssl`/`requests` в Python его не
поддерживает — потребуется либо:

- локальный TLS-терминирующий прокси (например, `stunnel`, настроенный
  через КриптоПро CSP), к которому этот клиент будет ходить по обычному
  HTTPS, либо
- сборка Python/OpenSSL с ГОСТ-движком (сложнее в поддержке).

В `EISConfig`/`EISClient` для этого ничего специально не сделано — они
рассчитаны на обычный TLS-сертификат или на то, что проксирование ГОСТ
решено на уровне инфраструктуры.
