# Оценка реализуемости: собственное ИИ-сопоставление работ с расценками (Агент 4)

Дата: 2026-09-18. Проверено вживую (браузер + прямой HTTP-запрос), не только по документации.

## TL;DR

**Источник данных для Агента 4 нашёлся, и он лучше, чем считалось раньше.** У ФГИС ЦС
есть открытый раздел данных (fgiscs.minstroyrf.ru → «Открытые данные»), который отдаёт
**полный ФСНБ-2022 (ГЭСН + федеральная база цен на материалы/машины) обычной прямой
HTTP-ссылкой, без логина, без ЕСИА, без крипто-клиента Jinn-Client**. Это меняет пункт 2
«Известных пробелов» в CLAUDE.md — раньше считалось, что доступ только через
веб-интерфейс+платный крипто-клиент, задокументированного bulk-доступа не было.

Но это закрывает только половину исходного вопроса. **Само «сопоставление работ с
расценками» — из вольного текста описания работ угадать нужный код ГЭСН — остаётся
отдельной, более сложной задачей**, для которой открытые данные дают сырьё (полный
текстовый каталог расценок), но не решение целиком. Ниже — что именно нашлось и почему
это меняет (или не меняет) картину.

## Что нашлось

На `fgiscs.minstroyrf.ru` в разделе **Открытые данные** — 15 наборов данных, доступных
без регистрации, с типовой открытой лицензией (data.gov.ru/normative_base):
разрешено воспроизведение, распространение, переработка и **коммерческое
использование** при условии ссылки на источник.

Из них ключевые для Агента 4:

| Набор | Формат | Что внутри |
|---|---|---|
| **ФСНБ-2022** | xml (zip) | Полная федеральная сметно-нормативная база: `ГЭСН.xml` (84 МБ, 30 028 позиций работ), `ГЭСНм/мр/п/р.xml` (монтаж/ремонт/пусконаладка), `ФСБЦ_Мат&Оборуд.xml` (45 847 расценённых материалов/оборудования), `ФСБЦ_Маш.xml` (машины и механизмы) |
| Классификатор строительных ресурсов | csv | Справочник кодов ресурсов |
| Ценовые зоны | csv | Территориальное деление для ценообразования |
| Среднемесячные размеры оплаты труда | csv | Базовые ставки труда по регионам |

Прямая ссылка на файл (пример, версия от 12.08.2026):
`https://fgiscs.minstroyrf.ru/api/values/GetFileContent/7f4f249c-9781-495c-9976-e795e0e8ed4e`
— проверено `curl` без каких-либо заголовков авторизации: HTTP 200, честный ZIP,
6.97 МБ сжатый / 48.5 МБ распакованный. Набор версионирован — на странице набора
перечислены ссылки на все версии с 2022 года с шагом в несколько месяцев (это,
кстати, готовый источник для Агента 10, если понадобится реальный, а не придуманный
региональный/федеральный индекс — надо будет отдельно проверить, публикуются ли там
же территориальные индексы, в этой сессии не проверял).

### Структура данных (что реально внутри `ГЭСН.xml`)

```xml
<Section Name="Земляные работы" Type="Сборник" Code="01">
  <Section Name="..." Type="Раздел" Code="1">
    <Section Name="..." Type="Подраздел" Code="1.1">
      <Section Name="Разработка грунта в отвал экскаваторами ..." Type="Таблица" Code="01-01-001">
        <NameGroup BeginName="Разработка грунта в отвал экскаваторами ... с ковшом вместимостью:">
          <Work Code="01-01-001-01" EndName="15 м3, группа грунтов 1" MeasureUnit="1000 м3">
            <Content>...текст состава работ...</Content>
            <Resources>
              <Resource Code="1-100-38" EndName="Средний разряд работы 3,8" Quantity="1.54" />
              <Resource Code="91.01.01-035" EndName="Бульдозеры, мощность 79 кВт" Quantity="1.6" />
              ...
            </Resources>
          </Work>
```

`ФСБЦ_Мат&Оборуд.xml` — то же дерево категорий, но на листьях реальная цена:
`<Resource Code="01.1.01.01-0002" Name="..." MeasureUnit="100 компл"><Prices><Price Cost="35537.67" .../></Prices></Resource>`.

То есть в связке ГЭСН (нормы расхода ресурсов на единицу работы) + ФСБЦ (цена
каждого ресурса) есть всё нужное для **ресурсно-индексного расчёта сметы**, если
известно, какая именно работа (код `Work`) и в каком объёме нужна.

## Два разных вопроса, которые важно не путать

1. **«У меня уже есть код ГЭСН/ФЕР и объём — посчитай стоимость».** Это не ИИ-задача,
   а обычный расчёт: взять состав ресурсов по коду, умножить на актуальные цены из
   ФСБЦ (с поправкой на регион/дату), сложить. Реализуемо полностью детерминированно,
   без ИИ вообще — просто нужен парсер XML и таблица цен. Технически несложно.

2. **«Вот описание работ из документации закупки текстом — угадай, какой код ГЭСН
   сюда подходит».** Это и есть то самое «ИИ-сопоставление», о котором был вопрос.
   Вот тут сложнее — см. ниже.

## Оценка реализуемости самого сопоставления (пункт 2)

**В целом реализуемо как вспомогательный инструмент с проверкой эксперта — не как
автономный точный сметчик.**

- **Подход:** классическая задача поиска по смыслу (retrieval/семантический поиск) —
  построить эмбеддинги по текстовым описаниям всех ~30 000+ позиций `Work`
  (`Section Name` + `NameGroup BeginName` + `Work EndName` + `Content`), и для
  входного текстового описания работы находить top-N ближайших кандидатов по
  косинусному сходству. Это стандартная, хорошо изученная техника, не требует
  обучения собственной модели — годится готовая модель эмбеддингов (в том числе
  русскоязычная открытая).
- **Реальная сложность — не в поиске, а в точности.** Формулировки ГЭСН очень
  параметризованы: соседние позиции отличаются группой грунта, объёмом ковша,
  классом напряжения, маркой бетона и т.п. — то, что для человека очевидная деталь,
  для похожего по смыслу, но неточного по параметру совпадения меняет стоимость
  существенно. Просто «похожий текст» — не гарантия «тот самый код».
- **Отсюда прямое следствие: выдача такого сопоставления обязана идти через
  экспертную проверку — что в проекте уже и так является обязательным правилом**
  для Агента 4 (протокол контроля качества, CLAUDE.md). То есть по факту это не
  новое ограничение, а совпадение с уже принятым решением: ИИ предлагает
  ранжированный список кандидатов, сметчик (сейчас — Edwin) подтверждает или
  поправляет, как уже устроено для Агента 3.
- **Что это НЕ решает — подсчёт объёмов.** Сопоставление «текст → код расценки»
  ничего не говорит о том, *сколько* единиц этой работы нужно (сколько м² кровли,
  м³ грунта и т.д.) — это отдельная, гораздо более сложная задача (чтение чертежей/
  проектной документации, обмер), которую этот источник данных не решает вообще.
  Без объёмов даже идеально угаданный код ГЭСН не даёт сумму сметы.
- **Открытый вопрос — региональная и временная актуализация цен.** `ФСБЦ_Мат&Оборуд.xml`
  даёт федеральную базовую цену на дату публикации; реальная цена в конкретном
  регионе на конкретную дату обычно требует умножения на региональный индекс
  пересчёта (то самое, что уже смоделировано как тестовые данные в Агенте 10,
  `regulatory_updates/sample_versions.py`). Публикуются ли эти индексы в том же
  открытом разделе — в этой сессии не проверял, стоит проверить отдельно, прежде
  чем проектировать Агента 4 целиком.

   эксперта), не как замена сметчика. Отдельно и заметно сложнее — подсчёт объёмов
   работ по проектной документации, для которого этот источник данных не подходит.
4. При любом использовании данных ФГИС ЦС — обязательна ссылка на первоисточник
   (условие открытой лицензии), не забыть при реализации.
